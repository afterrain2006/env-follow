# 自动创建项目环境：v0.4 讨论稿

状态：方案，尚未实现。当前可安装版本为 v0.3.0。

## 建议的使用体验

首次打开可信 Python 项目，没有 `.venv` 时显示一次「为此项目启用自动创建环境」。选择启用后保存项目级偏好；之后打开这个项目，不再逐次确认创建。

自动创建完成后面板显示项目 Python、环境路径与依赖缺失情况。依赖继续通过已有解析计划预览和用户确认安装；创建空环境不会顺带同步或升级包。

## 触发和设置

建议设置 `envFollow.autoCreateEnvironment`，取值 `off`、`prompt`、`auto`，默认 `prompt`：

- `off`：保持手动创建。
- `prompt`：每个项目只提示一次是否启用；拒绝后不随每次保存反复提示，可从设置改为 auto。
- `auto`：符合条件时自动创建空 `.venv`。

在打开/选择 Python 项目、首次保存 Python 文件、工作区由不可信变可信，以及设置启用时检查。普通扫描不反复触发创建；创建进行中，其他创建或 uv 修改操作应等待同一个项目操作锁。

首次版本只管理当前选定的本地项目；多根工作区通过项目选择逐个启用，避免打开一个工作区就批量创建所有环境。

## 创建条件与边界

1. 可信本地目录，存在 Python 项目线索，例如 `.py`、PEP 621 pyproject 或 requirements。
2. `.venv` 完全不存在，uv 可用，并找到符合项目要求的本机 Python。
3. 当前项目没有安装/同步/修复操作，且不属于暂不支持写入的 uv workspace。
4. 明确调用 `uv venv .venv --python <已检测的解释器> --no-python-downloads`，使用参数数组。

只创建 `.venv`，不初始化 pyproject、不修改 uv.lock、不导入 requirements、不安装依赖。现有「创建环境」实现会初始化声明，因此自动路径需要拆出独立的只创建环境操作。

已有 `.venv`、残缺目录或指向其他位置的链接均不覆盖、不清空。禁用继承的清空/强制覆盖/自动 seed 等 uv 环境选项，创建前再检查目标；处理多个窗口同时触发的竞争。

失败后显示真实原因和手动重试入口，并抑制本次会话中的重复自动重试。缺少符合要求的 Python 时提示选择或安装，不静默下载。

## 编辑器解释器

项目运行按钮继续明确使用项目 `.venv`。对于编辑器 Python，建议单独提供「创建后使用项目解释器」偏好：没有明确活动选择时可连接新环境；已有其他解释器选择时展示不一致与切换入口，避免悄悄替换用户的选择。

## 验收条件

- 启用后打开可信 Python 项目，自动生成有效 `.venv`，声明/锁文件/requirements 字节内容不变。
- 空目录、非 Python 项目、不可信工作区、不可用 uv/Python 和关闭设置均不自动创建。
- 重复保存、重复扫描及两个窗口并发时仅创建一次；已有或损坏环境保留。
- 不调用 add/sync/install，不联网下载 Python，不执行项目代码。
- 创建失败不会循环重试；重启或显式重试规则明确。
- 面板和解释器状态在完成后刷新，原有运行、预览与恢复行为保持正常。
